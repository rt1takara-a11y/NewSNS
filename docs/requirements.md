# 要件定義 — 最初のバージョン（MVP）

まず「つながりが消えても翌週また参加したくなるか」を体験できる**最小限**に絞る。
DM・動画・画像投稿・おすすめアルゴリズムは後回し。まず**文章と交流だけ**で試す。

## 実装更新（2026-09-08）

メールOTP・保存・交流・期間境界・通報・ブロックを実装。2026-09-23から日本時間の週次境界（月曜0:00）を採用。所有者からメール確認コードログイン、再読み込み後の保存、別端末と別アカウントでの投稿共有を確認済みとの引き継ぎあり。詳細はbackend-setup.md。

### 他ユーザープロフィール（2026-09-12）

- 投稿・返信・ユーザー一覧の名前/アイコンから今週の公開プロフィールを開く。
- 名前、アイコン、自己紹介、今週の投稿、フォロー/解除を表示。自分には編集リンクを表示する。
- 週次公開IDだけをURLに用いる。旧週のID、不明なID、ブロック・停止で不可視の相手は表示しない。
- 実接続時は表示前に再取得し、失敗時は再試行を案内する。月替わり・ブロックの反映は既存ストア同期を利用する。
- 投稿は既存の全体最新100件から抽出し、この上限を画面にも明記。個人別の全件取得は未実装。

## 最初に作る機能

| 項目 | 最初に作る内容 |
|---|---|
| 登録 | 非公開ログインID＋パスワード（メール不要、復旧なし）。既存メールログインも維持。内部アカウントは継続 |
| プロフィール | 週ごとに名前とアイコンを設定 |
| 投稿 | テキストのみ |
| 交流 | フォロー・いいね・返信 |
| タイムライン | 新着順・フォロー中 |
| リセット | 毎週月曜0:00（JST）に投稿・プロフィール・フォロー・いいね・返信を一括切替 |
| 再特定の防止 | 公開用IDも毎週変更。内部IDを画面や公開URLに出さない |
| 管理 | 通報・利用停止。停止されたアカウントは翌週も停止 |

## 毎週リセットのルール（このサービスの核）

- **リセットのタイミング:** 毎週月曜 00:00（JST）。ISO週番号で期間を識別する。
- **消えるもの（週ごとの情報）:** 公開プロフィール（名前・アイコン）、公開ID、投稿、フォロー、いいね、返信、ブロック。
- **残るもの（継続する情報）:** 内部アカウント、非公開ログインIDまたはメール認証との対応、利用停止状態、通報対応に必要な管理記録。
- **再特定の防止:** 公開IDは毎週新しく発行する。内部IDは画面にも公開URLにも出さない。利用者同士は前週の人を追跡できない。
- **利用停止の継続:** 停止されたアカウントはリセットをまたいでも停止のまま。

## 画面（最初に用意する4つ）

1. **タイムライン**（新着順／フォロー中の切り替え）
2. **投稿**（テキスト投稿・返信・いいね）
3. **プロフィール**（今週の名前・アイコン設定、その人の投稿一覧）
4. **リセット後の再スタート画面**（週初、まだ誰もフォローしていない状態からの導線）

## プロフィールのつながり表示（2026-09-13追加）

- 自分と他ユーザーのプロフィールに「フォロー中」「フォロワー」の人数を表示し、押すと一覧を開く。
- 一覧の名前・アイコンから、その人の今週のプロフィールへ移動できる。閉じるボタンとEscapeで一覧を閉じる。
- 人数は閲覧者に表示できる今週の人だけを数える。前週・利用停止・閲覧者または対象者との双方向ブロックに該当する人は人数にも一覧にも含めない。
- 取得中・通信失敗は人数を「—」とし、0人として扱わない。フォロー変更・プロフィール移動・週替わり時に古い一覧を再表示しない。
- 公開するのは週次公開ID・名前・アイコン・自己紹介。内部アカウントID・メールは返さない。

## 後回しにする（MVPに含めない）

- DM
- 画像・動画投稿
- おすすめ／レコメンドアルゴリズム
- 通知（プッシュ／メール）
- 検索（利用者による他ユーザー検索は、再特定防止の方針とも関わるので慎重に）

## 検証の進め方

1. **画面の試作品を作る** — タイムライン・投稿・プロフィール・リセット後の再スタート画面。
2. **ログインとデータ保存をつける** — 複数の友人が同時に使える状態にする。
3. **1週間周期でリセットを試す** — 投稿数より、リセット後に戻った人数と理由を確認する。
4. **周期を評価する** — 週次運用の結果を見て、間隔を維持するか再検討する。

## オープンな論点（未確定・要検討）

- 手動リセットを本番と同じ仕組みで運用する必要があるか。
- 利用者による他ユーザー検索を入れるか（再特定防止の方針と衝突しうる）。
- アイコンの扱い（画像アップロードは後回しなので、初期はプリセット／絵文字などで代替するか）。
