# 要件定義 — 最初のバージョン（MVP）

まず「つながりが消えても翌月また参加したくなるか」を体験できる**最小限**に絞る。
DM・動画・画像投稿・おすすめアルゴリズムは後回し。まず**文章と交流だけ**で試す。

## 実装更新（2026-09-08）

メールOTP・保存・交流・月次境界・通報・ブロックを実装。日本時間を採用。現在はSupabase未接続のため、本番稼働・メール実配信・複数端末の実認証は未確認。詳細はbackend-setup.md。

## 最初に作る機能

| 項目 | 最初に作る内容 |
|---|---|
| 登録 | メールでログイン。内部のアカウントは継続 |
| プロフィール | 月ごとに名前とアイコンを設定 |
| 投稿 | テキストのみ |
| 交流 | フォロー・いいね・返信 |
| タイムライン | 新着順・フォロー中 |
| リセット | 毎月1日に投稿・プロフィール・フォロー・いいね・返信を一括リセット |
| 再特定の防止 | 公開用IDも毎月変更。内部IDを画面や公開URLに出さない |
| 管理 | 通報・利用停止。停止されたアカウントは翌月も停止 |

## 毎月リセットのルール（このサービスの核）

- **リセットのタイミング:** 毎月1日 00:00（タイムゾーンは後で確定。まず JST 想定）。
- **消えるもの（月ごとの情報）:** 公開プロフィール（名前・アイコン）、公開ID、投稿、フォロー、いいね、返信。
- **残るもの（継続する情報）:** 内部アカウント、メールとの対応、利用停止状態、通報対応に必要な管理記録。
- **再特定の防止:** 公開IDは毎月新しく発行する。内部IDは画面にも公開URLにも出さない。利用者同士は前月の人を追跡できない。
- **利用停止の継続:** 停止されたアカウントはリセットをまたいでも停止のまま。

## 画面（最初に用意する4つ）

1. **タイムライン**（新着順／フォロー中の切り替え）
2. **投稿**（テキスト投稿・返信・いいね）
3. **プロフィール**（今月の名前・アイコン設定、その人の投稿一覧）
4. **リセット後の再スタート画面**（月初、まだ誰もフォローしていない状態からの導線）

## 後回しにする（MVPに含めない）

- DM
- 画像・動画投稿
- おすすめ／レコメンドアルゴリズム
- 通知（プッシュ／メール）
- 検索（利用者による他ユーザー検索は、再特定防止の方針とも関わるので慎重に）

## 検証の進め方

1. **画面の試作品を作る** — タイムライン・投稿・プロフィール・リセット後の再スタート画面。
2. **ログインとデータ保存をつける** — 複数の友人が同時に使える状態にする。
3. **短い周期でリセットを試す** — 初回はテストとして1週間程度で消し、翌日も戻ってくるか聞く。
4. **1か月の実験に進む** — 投稿数より、リセット後に戻った人数と理由を確認する。

## オープンな論点（未確定・要検討）

- リセットのタイムゾーンと正確な時刻。
- 「1週間テストリセット」を本番と同じ仕組みで手動発火できるようにするか。
- 利用者による他ユーザー検索を入れるか（再特定防止の方針と衝突しうる）。
- アイコンの扱い（画像アップロードは後回しなので、初期はプリセット／絵文字などで代替するか）。
