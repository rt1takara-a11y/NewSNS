# ロードマップ — 作る順番

投稿数を増やすことより、「リセット後に戻ってくるか」を検証することを最優先にする。

## フェーズ0: 準備（このコミット）

- [x] リポジトリに仕様ドキュメント一式を置く（docs/）
- [x] CLAUDE.md / AGENTS.md（AI開発ルール）を置く
- [ ] ホスティング・DB・認証の具体サービスを選定する

## フェーズ1: 画面の試作品

まずデータ保存なしでも良いので、4つの画面の見た目と流れを作る。

- [ ] タイムライン（新着順／フォロー中）
- [ ] 投稿・返信・いいね
- [ ] プロフィール（今月の名前・アイコン設定）
- [ ] リセット後の再スタート画面

## フェーズ2: ログインとデータ保存

- [ ] メールログイン（内部アカウントは継続）
- [ ] データベース接続（継続情報／月ごと情報を分けて保存）
- [ ] 公開ID発行のしくみ（内部IDを外に出さない）
- [ ] 複数の友人が同時に使える状態にする

## フェーズ3: リセットのしくみ

- [ ] 月ごと情報の一括リセット処理
- [ ] 定期実行（毎月1日）— まずは手動発火もできるように
- [ ] 利用停止の継続（リセットをまたいでも停止のまま）
- [ ] 短い周期（1週間程度）でテストリセットを実施

## フェーズ4: 運営・管理

- [ ] 通報
- [ ] 利用停止
- [ ] 通報対応の記録保持（画面からの削除とは別処理）

## フェーズ5: 1か月の実験

- [ ] 大学の友人 20〜30 人で実運用
- [ ] リセット後に戻った人数と、その理由を記録・分析

## 後回し（MVP後に検討）

- DM / 画像・動画 / おすすめアルゴリズム / 通知 / 有料広告 / アプリストア公開

## お金の方針

- 最初は有料広告やアプリストア公開にお金を使わない。
- 少人数で検証することを優先。費用は人数・保存量・選ぶサービスで変わる。
